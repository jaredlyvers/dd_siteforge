Setup, install, and the TUI

A terminal CMS for framework-native static pages. One Rust binary: edit a typed site tree, export HTML, host anywhere static.

What it is

You author a marketing site (roughly 5–20 pages, one editor) as JSON. The TUI edits that tree. Export writes static HTML plus CSS/JS from a Grunt build. There is no database, no multi-user CMS, and no server after export.

Workflow: init-site → drop images in source/images/ → TUI → npx grunt build → export or preview.

Install

You need a Rust toolchain (cargo) and, for CSS/JS, Node.js. From a clone of the repo:

./install.sh

Builds a release binary, installs it to $HOME/.local/bin/dd_siteforge, and copies the default theme to $HOME/.config/ldnddev/dd_siteforge_theme.yml only if that file is not already there. Override with PREFIX, BIN_DIR, or CONFIG_DIR.

# alternatives
cargo install --path .              # ~/.cargo/bin
cargo build --release               # ./target/release/dd_siteforge

./install.sh uninstall              # remove binary + theme

Confirm:

dd_siteforge --version
# dd_siteforge 1.7.0

Create a site

Pick an empty folder. init-site writes site.json, seeds Handlebars into source/templates/, and copies the Grunt / source/ / Lando / DDEV kit next to the JSON. Existing files are skipped.

mkdir my-site && cd my-site
dd_siteforge init-site site.json --name my-site

Without --name it prompts (or uses the folder name when stdin is not a TTY). Put author images in source/images/ (URLs in the TUI look like assets/images/hero.jpg).

CSS / JS

Host Node is the contract. Lando and DDEV are optional wrappers around the same commands.

npm install
npx grunt build          # or: npm run build

Writes web/assets/{css,js,webfonts}. npx grunt dev rebuilds on change. Optional: lando start then lando grunt build, or ddev start then ddev npm run build.

The editor

dd_siteforge tui site.json

Autosave rewrites the JSON 2s after a change. Manual s also writes a site.json.backup checkpoint. Ctrl+Q quits (confirms if dirty).

Tab / Shift+Tab still move between pages, not panes.

Edit a component

In Layout, j/k to a row and press Enter (or double-click). Tab between fields. Left/Right cycles enums. Ctrl+S saves; Esc cancels. In a URL field, Ctrl+P opens an image picker (source/images/) or a page picker.

Insert a component

/ opens a fuzzy picker. Allowed kinds follow the focused region: pages can insert hero/section/components; header can insert header-search/menu; footer cannot insert a hero.

Help and theme

Validate, export, preview

dd_siteforge validate-site site.json
npx grunt build
dd_siteforge export-html site.json ./web/
dd_siteforge serve site.json          # export + http://127.0.0.1:8765/

Inside the TUI: F3 validate, Shift+E export (prompts for a directory the first time, then remembers export_dir), p export + local HTTP + open the current page in a browser.

Export copies Grunt web/assets (unless the dest already is that tree), fills missing webfonts/favicon from source/, copies source/images/ → web/assets/images/, and writes sitemap.xml, robots.txt, and 404.html when you have no author 404 page.

Validation and export refuse to run when slugs collide, required fields are empty, or a local assets/images/… file is missing next to the JSON.

Theme

First file found wins:

  1. ./dd_siteforge_theme.yml (project)
  2. ~/.config/ldnddev/dd_siteforge_theme.yml (user)
  3. Built-in defaults

Must declare version: 1. Token names are in LDNDDEV_TUI_VISUAL_STANDARD.md. Optional header_quotes replaces the rotating header line (picked once per launch).

dd_siteforge show-site site.json

Updating these screenshots

PNGs live in docs/tutorial/images/. Names are a contract with this page. The full procedure is SCREENSHOTS.md.

On Hyprland (foot + grim + wtype):

cargo build --release
./docs/tutorial/capture.sh

That seeds a throwaway site under /tmp/dd_siteforge_tutorial/, pins the header quote, drives the TUI through the table in SCREENSHOTS.md, and overwrites the eight PNGs. Inspect them, then:

git add docs/tutorial/images/*.png
git commit -m "docs: refresh tutorial screenshots"

Do not commit site.json or the /tmp scratch site. Manual capture: 132×42 terminal, same key sequence, window-only screenshot, same filenames.
